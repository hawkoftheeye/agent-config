# PR Review Classification

## Critical

Use when the issue is likely to cause:

- incorrect behaviour
- data corruption or loss
- security vulnerabilities
- significant production failures
- broken compatibility or contracts

Critical findings should normally be addressed before merge.

## Important

Use for significant maintainability, reliability, performance,
architecture, or correctness concerns that should ordinarily be addressed
before merge but are not immediately dangerous.

## Advisory

Use for optional improvements such as:

- readability
- naming
- simplification
- minor refactoring
- alternative implementation approaches

Clearly communicate that these comments are non-blocking.

## Strength

Use for particularly good implementation choices worth reinforcing.

Do not add praise merely to balance negative comments.
Only publish strengths that are specific and meaningful.
